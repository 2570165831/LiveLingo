# macOS 14 外观验收清单

基线：`2f19cba`；第一版修复：`ef81c92`；本次候选：包含本清单的 K1–K5 修复提交。执行前分别记录完整提交号、构建号、系统版本、主题和截图文件名，不能混用不同分支的 App。

本轮只更新清单和宿主测试，不操作 VM。下列步骤供有 VM 测试授权的执行者使用；协调正在使用该 VM 的测试任务，只改变测试 VM 的设置。材料必须是合成文本，不下载或加载模型，不录音，不使用真实课堂或账号数据。

## 必须先满足的条件

1. 在同一台 macOS 14 VM 中先将系统强调色设为 **Blue**，记录实际设置。完成全部普通对比后，再设为 **Red**，重复启用控件的取色与主题检查。不能用系统 Graphite 或未知强调色作为唯一验收环境。
2. 每次拍摄和取色前，激活被测 App，点击目标窗口；记录 `NSApp.isActive`、`window.isKeyWindow`、`window.isMainWindow` 都为真。截图中的彩色交通灯是辅助证据。sheet 出现时，检查其实际承载窗口的 key 状态；不能拿失焦主窗口的灰色控件证明修复生效。
3. 先运行基线，在亮色和暗色的活动窗口中分别保存“跟随最新”开启、原生选择控件开启、工具栏主按钮启用的截图。记录跟随按钮是否呈系统蓝、主按钮是否缺少实心填充。第二次强调色测试同样保存基线。
4. 再运行第一版修复和本次候选，用同样的窗口尺寸、主题、合成状态、取样位置和截图方式复测。若基线在活动窗口下没有复现某个原始症状，记录“基线未复现”，该症状不能直接判为修复通过。
5. 截图统一转换到 sRGB。用控件内部远离文字、图标、边缘和高光的 3 × 3 区域，记录坐标及 RGB 各通道中位数。禁用、按下、悬停、非活动状态分别记录，不能混入普通启用态取色。保留原图和标注取样区域的副本。

## 逐控件判据

项目石墨灰：亮色 `#636366`（99, 99, 102），暗色 `#747479`（116, 116, 121）。这些值仅用于使用 `ClassroomPalette.accent` 的活动、启用控件。

| 控件与状态 | 普通启用态的判据 | 必须保存的对照 |
| --- | --- | --- |
| 工具栏“开始记录”及“结束并保存 / 结束记录” | 本次候选有连续实心填充；内部取样与主题对应石墨灰每通道偏差不超过 2；文字和图标使用 `onAccent` 语义色 | 基线、第一版、本次候选，亮暗各一组；启用与禁用分开 |
| “跟随最新”开启 | 与同主题原生 `.gray` 对照控件的内部样本每通道偏差不超过 8，不能用上述主强调色代替；必须记录对照的实际 RGB | 基线、第一版、本次候选；另与 15+ `.tint(.gray)` 的活动窗口样本对照，记录系统版本与原生渲染差异 |
| 窄窗口“字幕 / 笔记”分段选择器 | 选中段中心样本接近主题对应石墨灰，每通道偏差不超过 8 | 每个段分别选中；基线与本次候选同位置对照 |
| 设置中的“专注模式”“防止空闲睡眠”及使用强调色的选择器 | 每个可用控件的选中区域分别取样，接近石墨灰，每通道偏差不超过 8 | 逐控件开关或逐选项记录，不能用一个 Toggle 代表整页 |
| “文字翻译”sheet 的“翻译” | 输入合成短句使按钮可用后，填充中心接近石墨灰，每通道偏差不超过 8；空输入的禁用样本另记 | sheet 自己的活动窗口截图；无需执行翻译 |
| “复查笔记”队列主动作、“录音处理”采用文字的主动作 | 在合成候选或合成队列中逐个取样，接近石墨灰，每通道偏差不超过 8 | 启用、空队列或无候选禁用态分别截图；不执行真实复查或采用真实材料 |

Blue 与 Red 两轮中，本次候选的同一控件样本每通道变化也不得超过 8。基线样本应同时保留以证明测试能看见系统强调色影响；不要把“看起来是灰色”当成取色结论。原生高光、阴影不按基础 hex 判定，但不能借此跳过所有填充内部样本。找不到可测的填充区域、超出阈值或对照来源缺失时，记“失败 / 未测”及原因，不临时放宽阈值。

`.gray` 对照须在同一测试窗口使用原生按钮式 Toggle，明确设置 `.tint(.gray).accentColor(.gray)`，先记录实际 RGB。它用于排除系统强调色和失焦造成的灰色；15+ 对照仍使用原有 `.tint(.gray)`。不要把系统强调色 Graphite 的取样值误当作项目石墨灰或 `.gray`。

无模型时可使用合成、启用的 hosted toolbar/control fixture 验证原生集成，截图明确标记“测试宿主”。真实 App 中模型未就绪的禁用按钮不能证明启用态填充通过；若只能检查禁用态，真实 App 的启用态必须留为“未测”。macOS 14 不支持同步初译属于既有功能限制。

## 主题、非活动态与交互

1. 亮暗主题各检查宽窗口（1260 × 820）和窄窗口（820 × 700）。切换主题时，主窗口、设置和已打开 sheet 更新颜色，布局及控件顺序不变。
2. 非活动态另拍一组：先拍活动窗口，再将其他测试窗口设为 key，确认被测窗口不再 key。14 的自绘主按钮应使用 `unemphasizedSelectedContentBackgroundColor` 和 `unemphasizedSelectedTextColor`，与活动石墨灰有可见区别；重新激活后恢复普通填充。非活动截图不能用于上面的修复通过判定。
3. 开启 VM 的 **Increase Contrast**，与同主题普通状态对照；14 自绘主按钮应出现 1 pt 的语义标签色轮廓，启用、禁用、非活动态均不丢失轮廓。原生 `.bordered` 对照按钮的轮廓也须截图。
4. 开启 VM 的 **Reduce Transparency**，复测明暗主题、活动及非活动工具栏，文字可读、填充稳定、不出现透明空洞。记录实际设置及截图。
5. 鼠标移入、移出、按下、移出后释放再返回：标签不消失，命中区覆盖可见按钮，无永久按下态。禁用按钮不执行动作。“更多”、暂停/继续和浮动字幕保持原有次级外观。
6. 使用合成字幕验证“跟随最新”关闭后可阅读旧字幕，开启后新字幕自动跟随。动作与色彩分别判定；合成主按钮验证一次点击只触发一次，禁用不触发，不连接录音或模型服务。

## 键盘与辅助功能

1. 先在 VM 的 System Settings > Keyboard 中开启 **Keyboard navigation**，记录状态，再用 Tab / Shift-Tab 到达主按钮和“跟随最新”。不能在该开关关闭时把无法到达控件判为样式失败。
2. 在同一窗口放置原生 `.bordered` 对照按钮；截图比较焦点轮廓是否可见、位置是否包围按钮。检查自绘按钮的焦点不会被填充或高对比度轮廓遮住。空格触发启用按钮；禁用按钮不执行。
3. VoiceOver 检查标题、按钮角色、禁用状态及 Toggle 的开关状态。只读 hosted accessibility 树不能代替实际 VoiceOver；未执行就记录“未测”。检查中文标题、图标、焦点轮廓没有裁切。

## macOS 15+ 回归与记录

macOS 15+ 保留原生 `.borderedProminent` 和原有 `.tint` 链。另在获准的 26.5.2 与 27 VM 中对比基线、第一版和本次候选的真实活动窗口截图，明暗、启用、禁用分别记录。宿主 `cacheDisplay` 像素相等不覆盖 26+ 的完整玻璃合成层，不能替代这些截图。

宿主测试使用测试专用 `NSWindow` 强制 key/main 查询，并注入 `.key` 控件状态；抓图时仍断言 key/main，启用原生突出按钮必须实际包含石墨灰像素。这不证明宿主 App 真正成为了前台应用。高对比度轮廓通过 DEBUG 专用输入测试相同绘制分支，不能代替 VM 上的系统开关联动检查。故意把更新侧 tint 改成红色，必须使与正常回归共用的像素相等断言失败。严格的 expected-failure 检查若没有捕获失败，整个测试应失败。

每条记录以下字段，不预填通过：提交、系统版本、主题、强调色、窗口 active/key/main、控件及状态、截图名、取样坐标、基线 RGB、候选 RGB、参考 RGB、最大通道偏差、通过 / 失败 / 未测、原因。截图及记录不包含真实课程、个人保存路径或账号信息。

最终分别判定：原始症状复现、固定石墨灰、跟随最新的 `.gray`、真实工具栏填充、非活动态、高对比度、减少透明度、鼠标、键盘、VoiceOver、15+ 真实外观。任何“未测”均保持为未测，宿主分支选择或注入环境测试不能替代真实 macOS 14 / 15+ 的结果。
