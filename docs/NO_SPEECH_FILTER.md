# 未识别到讲话

录音、文件导入和命令行回放共用磁盘转写队列。自动转写先对保存好的块音频运行系统 SoundAnalysis 的 `version1` 分类器：窗口 1.5 秒，重叠比例 0.5，只取 `speech` 标签的最大置信度。最大值严格小于 0.1 才拦截；等于门槛放行。常量和可注入分析接口集中在 `SpeechPresenceGate.swift`。

文件分析器会遗漏不足一个步长的末尾。实现检查实际窗口覆盖；尾部未覆盖时，读原块最后 1.5 秒并用内存流分析补上，取两次分析的最大值。读取时处理短读，不补零、不借相邻块的声音、不写临时音频。原前缀存在分析缺口或尾部分析无法完成时放行。公开字幕标注的短“Yes.”放在两秒块末尾，是这条行为的回归夹具，来源和许可随夹具保存。

命中后不会调用 Parakeet、增强识别、备用识别或语言探测，不产生正式字幕，也不进入翻译或笔记。转写任务显示“未识别到讲话”，保留音频、原始时间范围及本次置信度，不自动重试。用户可以在录音处理窗口点“重试这段”；手动重试绕过新增分类判定，包括退出后重新打开课程再重试。

过滤保护的是保存块的正式转写及后续正文翻译、笔记。Apple 实时预览和临时初译可能在块保存、判定前显示；它们继续使用既有路径。命中发送该块的范围清除事件，按既有完整覆盖规则处理；跨块预览或后续 Apple 结果不保证立即、永久隐藏。本功能没有实现实时预览的人声门控。

不足 1.5 秒、分类器不可用、分析失败、没有有效窗口或无效置信度均放行。短话不补零，以免稀释真实人声。已有数字静音检查仍保留，手动重试绕过的是新增分类判定。已有文字或待确认候选的范围不被新判定清空。测试注入的识别器默认不调用外部分类器，可另外注入 `speechAnalyzer` 验证过滤行为。

拦截记录使用 `status: silent`、`extendedStatus: noSpeech`、`failureReason: noSpeech` 和可选 `speechConfidence`。当前版本按扩展状态读取；旧版把它当终态静音，不会重新送进自动识别。旧版不会显示新增标签或提供该状态的专用手动重试入口，而且旧版改写可能丢失扩展字段。需要恢复误判时使用支持本功能的版本。

课程快照仅在拦截数量大于零时保存可选的 `processing.noSpeechCount`，它只用于显示。转写日志保存具体块的状态。这个可忽略的显示字段不提高现有阅读版本；其他课程字段触发的版本 2 或版本 3 限制仍然生效。兼容编码不代表旧版能读取任何新版课程，旧版 GUI 未在本任务中运行。

状态详情、命令行计数和转写问题统计可以看到拦截数量。无人声终态不计入待处理、转写失败或遗漏人声时长。正常字幕、翻译请求、笔记和导出继续沿用原流程；未拦截时不增加置信度和零值计数字段。

本地统计入口为 `Scripts/nsfilter-private-stats.py`，只输出统计，不输出课程原文。其整文件窗口覆盖诊断与产品逐块重新分析的方法不同，应分别解释。公开音频评估脚本和回执记录测量范围、官方字幕时间精度及 CPU/能耗限制；分类器置信度不是错误率保证，远处或很弱的人声仍可能被拦截。
