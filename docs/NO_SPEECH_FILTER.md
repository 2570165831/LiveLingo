# 未识别到讲话

录音、文件导入和命令行回放共用磁盘转写队列。数字静音检查先执行，仍使用原有 `DigitalSilenceGate` 的规则和 `silent` 终态；不会为了零值音频运行声音分类器。

新增门控是多信号的保守判定，不能仅凭 SoundAnalysis 的低分丢掉一块音频。已有正文、待确认候选、该块对齐的 Apple 预览文字，以及识别器返回的任何非空文字（包括数字、中文和其他非英文），均否决无人声判定。Apple 空值只是封块时的快照，不代表实时识别已经完成；本功能不清除已显示的预览，也不拦截后来的 Apple 结果。

只有同一份原块音频满足下面全部条件，才标为“未识别到讲话”：

- 当前及历史均没有手动重试，没有已有正文、候选或 Apple 文字，也没有识别器返回的文字。
- Parakeet 明确验证了输出词元与置信度记录一致：有词元时，平均值低于 0.90 且最小值低于 0.05；没有词元且正文为空时，平均值和最小值合法地不存在，不把它们编成零。任一置信度达到门槛、仅缺一个数值、旧服务未提供有效性标记、无效观察及识别错误均放行。
- 现有调度已经取得有效语种探测结果。必须明确返回 `None` 标签、其概率至少为 0.55 且英语概率低于 0.55；低置信度的具体语言只是证据不足，不能当作无人声。所有具体语言、待共识的语种以及未知/失败的探测均放行。
- SoundAnalysis `version1` 的 `speech` 最大置信度严格低于 0.1。等于门槛放行；窗口仍为 1.5 秒、重叠 0.5。分类器不可用、报错、无有效窗口、不足 1.5 秒或覆盖不全均放行。
- 从识别开始到判定结束，原块音频的 SHA-256 没有改变；指纹无法读取时放行。异步结束写回时再检查最新正文、候选及手动重试状态。

判定复用原有 `languageProbe` 路径，排在 `deferSource` 之后，不新增提前探测，不抢占正式转写积压，不绕过按块序号处理的语种共识。因前序尚未完成而延期的块直接沿用原流程；`sourceOnly` 不执行无人声判定。缺任一证据意味着减少过滤，而不是推断为无人声。

只有识别和语种证据都支持继续判定时才运行声音分类，避免对已认出讲话的块再分析。分类结果（包括不可用结果）按块 ID 和音频 SHA-256 缓存在当前队列代次内，上限 64 项；同音频的自动补转复用结果，波形改变则重新分析，显式重试、终态和新队列代次释放缓存。不保留 PCM、不写入会话档案。窗口重叠保持原值，以免节能改动漏掉跨窗短话。

相对原来的识别前单分类拦截，新判定让无讲话块也先承担既定识别和语种头的成本，换取已有讲话证据的保护。缓存减少的是重复声音分类，不能据此宣称总功耗、GPU 时间或续航改善；这些没有在本任务中实测。

本轮仅重计既有公开评测的保存结果，没有重新运行识别或读取课堂音频：155 个评测块对应 154 份不同 PCM，拦截 0 块；其中 96 块有参考词时间重叠、11 块在无词字幕区间、48 块没有时间标注。所有 155 块的主识别或 fallback 至少一项返回了非空文字，所以 13 个 `None` 语种头也不足以支持拦截。保存的门控调用计数为主识别 155、fallback 32、语种头 78、声音分类 0；评测器提前准备过识别结果，这些是门控路径请求计数，不是实际模型计算次数或能耗。来源是 `work/nsfilterfix/public-real-asr-asr-runtime/block-results.jsonl` 的逐行重计，并与该目录的 `receipt.json` 和 `verification.json` 对照。此样本没有证明减少自动补转、总功耗或续航收益，真实无人声拦截率仍未知。

文件分析器会遗漏不足一个步长的末尾。实现检查实际窗口覆盖；尾部未覆盖时，读原块最后 1.5 秒，用内存流补分析并取最大值。不补零、不借相邻块、不写临时音频，任一分析缺口均放行。公开字幕标注的短“Yes.”放在两秒块末尾，是回归夹具，来源和许可随夹具保存。

命中后只进入单独的“未识别到讲话”终态，不发表正式字幕、不进入翻译和笔记，不发红色转写问题提示，也不记为 `transcription_missing`。增加 `transcription_no_speech` 诊断事件和无人声计数，并撤回同一时间区间已有的 `transcription_missing` 诊断及提示；其他区间和重试历史保留。前序语种尚未完成导致空块首轮延期时，缺失诊断和红色提示等到自动补转的完整判定；如果补转仍失败，照常报缺失。恢复已保存的无人声终态也重新撤回其遗留提示，不重跑识别或增记一次分类事件。音频和原时间范围保留，不自动重试。用户点“重试这段”后，整条修复链（包括后续自动重试、邻接音频候选和重新打开会话）持续绕过新增门控，原数字静音检查仍保留。

生产队列通过 `DurableTranscriptionJournal.markNoSpeech` 写入终态，在日志锁内再次核对最新正文、候选和手动重试历史。异步判定期间新增的正文保留为已完成；只有候选、正文仍为空时，有自动重试额度就保持待补转，额度耗尽则保留有明确原因的失败状态，不清空候选或保存无人声置信度。

## 与流式声音分类的对接

本分支没有合入 alarm 分支。可复用位置是 alarm 分支 `AlarmSoundAnalyzer.Observer.request(_:didProduce:)`：同一 `SNClassificationResult` 同时含警报和 speech 标签，可以在原回调提取 speech 分数及时间范围；`SpeechPipeline.refreshAlarmAnalysis` 的 generation、alarmAnalysisID 和 `alarmWrittenFrames` 已提供代次及 PCM 时间轴。对接后可在 `rotateCurrentChunkLocked` 为封块汇总完全覆盖其帧范围的结果，将最大值交给队列，避免再建文件分析器。

现有 `SpeechActivityDetector.request(_:didProduce:)` 同样已有流式分类，但只输出阈值化 Bool，不能把 false 当成 speech < 0.1；需要保留实际分数、标签、覆盖范围和失败状态。流式阳性可以直接否决无人声；流式阴性必须覆盖整个块并绑定同一 PCM/代次。alarm 流目前只分析麦克风，暂停会重建，也可能丢帧，三秒窗口与本门控的一点五秒窗口不同；系统内录、导入、覆盖缺口和短块不能套用其低分。未完成这些绑定前不使用流式阴性作拦截证据。本分支先以按需分类及缓存减少重复工作。

拦截记录使用 `status: silent`、`extendedStatus: noSpeech`、`failureReason: noSpeech` 和可选 `speechConfidence`。当前版本按扩展状态读取；旧版把它当终态静音，不会重新送进自动识别。旧版不会显示新增标签或提供该状态的专用手动重试入口，而且旧版改写可能丢失扩展字段。需要恢复误判时使用支持本功能的版本。

课程快照仅在拦截数量大于零时保存可选的 `processing.noSpeechCount`，它只用于显示。转写日志保存具体块的状态。这个可忽略的显示字段不提高现有阅读版本；其他课程字段触发的版本 2 或版本 3 限制仍然生效。兼容编码不代表旧版能读取任何新版课程，旧版 GUI 未在本任务中运行。

状态详情、命令行计数和转写问题统计可以看到拦截数量。无人声终态不计入待处理、转写失败或遗漏人声时长。正常字幕、翻译请求、笔记和导出继续沿用原流程；未拦截时不增加置信度和零值计数字段。

本地统计入口为 `Scripts/nsfilter-private-stats.py`，只输出统计，不输出课程原文。其整文件窗口覆盖诊断与产品逐块重新分析的方法不同，应分别解释。`nsfilter-probe`、`nsfilter-evaluate.py` 与私密统计只测声音分类这一项；其低分拦截代理不是本版多信号门控的实际误删率。新门控评估须另外绑定同块真实识别与语种结果，不能仅用参考字幕模拟识别证据。公开评估和回执记录测量范围、参考时间精度及 CPU/能耗限制；分类器置信度不是错误率保证，真实讲话仍可能在多信号都失败时被拦截。
