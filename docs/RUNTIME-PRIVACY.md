# App runtime privacy repairs

Scope: P01–P08 of the runtime audit, based on `121be45`. All probes use synthetic inputs. No classroom containers or course data were inspected. No networking, real inference, GPU workload, installation, signing, or publishing was performed. Root Python discovery pins synthetic tensor tests to the CPU.

## Existing data and worker identity

Existing courses are retained. Permission migration removes group/other access and allow ACLs while preserving explicit owner read-only restrictions and deny ACLs. It does not change transcript/note bytes. App-owned temporary roots and per-write pending files are the cleanup boundary. Historical diagnostics and pending files with unknown ownership remain; they are not bulk-deleted. Owner/type/symlink conflicts stop the affected operation.

The runtime identity hashes `worker.py`, `engine.py`, review diagnostics and the new `checkpoints.py` module. The baseline worker already differs from v0.2.0; this repair changes its hash again. Old incompatible model checkpoints are not reused and require regeneration from the retained application journal. Course `inputFingerprint` is separate and remains covered by frozen regression tests. The runtime assembler, bundler and verifier now include the new module. No installed runtime or signed release was updated.

## Evidence and limits

The local red receipts are `privacy-all-red.log` and `python-red-green/red.json` under the task validation directory. They show pre-repair failures for each finding: volatile checkpoint retention; failed-write leftovers; diagnostic body/error exposure; default snapshot body retention; public modes; linked writes; missing authentication; unsafe HTTP targets/shared transport. Initial compilation/interception fixture mistakes are not counted as vulnerability evidence. New hardening checks additionally cover ACL preservation, overlapping checkpoint writes, foreign pending files, shutdown and saved-course preservation.

Final gates:

- `xcode-full-final.log`: XCTest 1146 tests, 1 skipped, 0 failures; Swift Testing 187 tests, 0 failures.
- `check_build_warnings.py`: PASS, 0 compiler warnings. `check_test_preferences.py`: PASS, 267 created/267 cleaned UUID suites; all corresponding plists absent.
- `python-acceptance.log`: 705 tests, 6 skipped, no errors. The only two failing subcases are the known baseline CPU precision assertions in `ProbePrecisionTests.test_bfloat16_logits_normalize_to_one_with_float32_precision` (`top=16.0`, `top=-1000.0`). No tolerance or inference math was changed.
- `final-cli-receipts.json`: multilingual, translation-failure, target-review, target-acceptance, learning-quality and learning-quality-target executables all exit 0. These binaries were rebuilt after the final runtime changes.
- Golden summary, 630-row verdict fixtures and `test_grammar_bytes.py` are unchanged from `121be45`; full tests additionally cover EE06, export constants, zh-Hans snapshots and `inputFingerprint`.
- The test host temporarily used the task-owned TMPDIR through its scheme. That routing-only scheme edit was restored before committing; application source and tests above were unchanged by restoration.

 HTTP tests use memory transports and unbound handlers. Synthetic tensor tests load no weights. These results do not establish installed-app acceptance, real model output equivalence, native-server redirect behavior, crash/forced-quit cleanup, or historical data removal. Forced termination can prevent application cleanup; unknown historical files are retained to protect user data. Permissions do not stop synchronization by the owner’s cloud account.
