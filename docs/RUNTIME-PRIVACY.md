No networking, real inference, GPU workload, installation, signing, or publishing was performed. Root Python discovery pins synthetic tensor tests to the CPU.

## Existing data and worker identity

Existing courses are retained without automatic permission migration: opening and reading do not alter bytes, mode or ACL. An explicitly requested save may replace content, but preserves existing access constraints and refuses effective write denial. No existing user course or credential was accessed in this repair. App-owned temporary roots and per-write pending files are the cleanup boundary. Historical diagnostics and pending files with unknown ownership remain; they are not bulk-deleted. Owner/type/symlink conflicts stop the affected operation.

The runtime identity hashes `worker.py`, `engine.py`, review diagnostics and the new `checkpoints.py` module. The baseline worker already differs from v0.2.0; this repair changes its hash again. Old incompatible model checkpoints are not reused and require regeneration from the retained application journal. Course `inputFingerprint` is separate and remains covered by frozen regression tests. The runtime assembler, bundler and verifier now include the new module. No installed runtime or signed release was updated.

## Evidence and limits

The follow-up synthetic red/green receipts and complete test logs are retained under the task's `work/privacy-followup` directory. Storage probes reproduce the prior directory-replacement, ACL-only access, read-only/deny-write replacement and ordinary-advice counterexamples. Production regression tests cover disk reload of failed cleanup records, non-cooperative tasks/full anonymous pipes, secure audio creation and installer token ACLs. Prior repair numbers are historical baseline evidence, not this follow-up's acceptance result.

The default Chinese golden summary, 630 verdict rows, EE06, export constants, zh-Hans course snapshots, inputFingerprint and grammar byte assertions remain unchanged. Tests run synthetic data and substitute workers; no model or GPU is used. A local acceptance receipt records final counts and any known CPU precision rerun.

These checks do not establish installed-app acceptance, native AppKit quitting, real audio capture/model output, crash/forced-quit cleanup or cross-user/cloud filesystem behavior. Forced termination can interrupt cleanup. Unknown historical files, active cleanup records and preserved migration copies are retained. A user-modified existing permission or ACL is deliberately retained, so old non-private storage is not claimed to have become private. Permissions do not stop synchronization by the owner's cloud account.
