# 隐私边界 / Privacy boundaries

苹果初译会把预览文字交给 macOS 的翻译框架；语言准备由系统管理，未安装的语言可能需要下载。本仓库没有验证系统内部的通信或留存，因此本机模型处理不代表整个应用在所有情况下都完全离线。点击“复制译文”会把译文写入系统全局剪贴板，具备访问能力的其他应用或剪贴板管理器可能读取它，跨设备传播取决于通用剪贴板等系统设置。保存或导出到共享、同步目录后，内容还受对应服务的访问规则影响。质量、benchmark、验收、校准和评分报告默认输出汇总，正文需显式开启。CLI 译文、恢复录音、scoreboard 私有原始证据及模型状态仍可能默认包含正文；其中 scoreboard 的 `.translation-content` 输入和输出不由报告的正文开关控制。Swift 在文件系统支持时，新建私有对象限制权限并清除继承 ALLOW ACL，保存和导出在替换前核对新文件的权限及可用 ACL。权限回退同时考虑调用的错误和文件描述符所绑定的卷：APFS/HFS 支持这些属性，单次调用失败（包括意外 ENOTSUP）会报错；FAT/exFAT 等无此能力的卷以及其他卷明确返回 ENOTSUP/EOPNOTSUPP/ENOSYS 的情况才允许回退。已经读到的旧 ACL、owner/group 和 mode 仍须保持或不放宽，无法满足就报错保留原件。APFS 等支持的卷上，意外的权限或 ACL 读取/设置错误会向上层报错，保留原文件，失败的新建私有文件不提交并清理本次临时件，可在故障解除后重试。工具不修改已有对象的权限。权限限制不能阻止当前用户自己的同步软件。恢复副本与模型状态应保留在私有位置，交付前检查最终包。

Apple preview translation passes preview text to the macOS translation framework. Language preparation is managed by the system and may require a download when a language is not installed. This repository has not verified the system's internal communication or retention, so local model processing does not establish that the entire app is always completely offline. Clicking “Copy translation” writes the translation to the global system clipboard; other apps or clipboard managers with access may read it, and cross-device transfer depends on system settings such as Universal Clipboard. Saved or exported content in shared or synced folders is also subject to that service's access rules. Quality, benchmark, acceptance, calibration and scoring reports contain summaries by default and require explicit opt-in for content. CLI translations, recovered recordings, private scoreboard evidence and model state may still contain content by default; scoreboard's `.translation-content` inputs and outputs are independent of report content switches. Where supported, Swift restricts newly created private objects, removes inherited ALLOW ACLs, and checks the replacement inode's permissions and available ACL before committing. Permission fallback considers the error and the descriptor-bound filesystem. APFS/HFS support these attributes, so a failed call, including unexpected ENOTSUP, is reported. FAT/exFAT capability gaps and explicit ENOTSUP/EOPNOTSUPP/ENOSYS on other filesystems permit portable fallback. Already observed ACL, owner/group and mode constraints must still be preserved or remain no broader; otherwise the save fails and preserves the original. Unexpected permission or ACL read/update errors on supported volumes such as APFS are reported to the caller: the original file stays intact, failed new private files are not published, and this attempt's temporary file is removed. Saving can be retried after the fault is resolved. Tools do not change permissions on existing objects. File permissions do not prevent the current user's own sync software from copying it. Recovery copies and model state should remain private; inspect the final package before sharing it.


## 已知限制 / Known limitations

- 同一用户下的恶意程序仍可能在创建目录与绑定目录、末次身份/权限检查与替换之间抢换对象。R01（临时根身份绑定与清理）、R04（已有对象权限不迁移及目录创建）、R05（保存替换）、R07（恢复副本）和 R08（checkpoint）的这些竞态残余本轮未增加复杂防护；普通静态软链接、非普通文件和已知身份变化的检查仍保留。Python 生产 checkpoint 序列化绑定已打开的文件描述符，但末次检查到 `os.replace` 之间仍有竞态，兼容的文件名回调接口也仍有路径竞态。这些措施不能隔离持有同一用户权限的恶意程序。
- exFAT/FAT32、部分网络卷及外接盘可能不支持 Unix 权限、ACL、硬链接或扩展 rename 原语。Swift 先核对绑定描述符的卷，APFS/HFS 上权限调用失败不回退；FAT/exFAT 的 ENOTSUP/EPERM/EXDEV 等能力错误及其他卷明确不支持的权限能力可回退，但不能借此丢弃已读取的原 ACL、改变 owner/group 或增加 mode 访问位；EPERM、EACCES、EIO、EXDEV、EINVAL 等权限错误不会被静默忽略。硬链接或扩展 rename 不可用时仍可使用同目录普通 rename（该类操作的 EPERM/EXDEV 也允许回退）。这不保证不支持权限的卷上的文件仅当前用户可读，也不保证普通 rename 具备 APFS swap 的全部检查和回滚能力。用户主动共享或同步目录仍服从该服务的规则。
- Python checkpoint 的拒绝条件单独保留：部分可选元数据错误只有在新文件没有增加原 mode 的访问位、且最终 ACL 与应保留的约束一致时才可继续；无法保留既有非空 ACL、ACL 读取出现 EPERM 等非能力错误，或新文件清除继承 ALLOW ACL 失败时，会报错并拒绝提交。生产保存的序列化回调绑定已打开的文件描述符；恢复读取 `load_checkpoint` 仍给回调传文件名，不能据保存绑定推断恢复读取也已绑定。
- 退出只限制没有实际存储进展的等待；已经运行的课程保存和导出可以报告成功写入的字节并延长等待。普通停止不使用退出截止。清理真正挂起或失败时，可明确选择“仍要退出”：保留已经写到磁盘的文件，尚未写入的进度可能丢失，未清完的暂存文件以后重试。同步内核 I/O 若阻塞主线程，计时器不能保证界面按固定时长响应。
- P09：系统初译仍未增加统一的离线门槛。macOS 翻译框架管理语言包准备，可能需要下载；系统内部通信和留存没有在本仓库得到验证。
- P10：复制译文仍使用系统全局剪贴板，其他具备访问能力的软件可能读取它，通用剪贴板设置还可能使它跨设备传播。
- 正常资源支持限于格式可识别的 `py.typed`、非执行型相对路径 `.pth`、公有证书 PEM，以及资源目录或 `.lproj` 中的 OpenStep `.strings`。未知二进制、执行型 `.pth`、私钥和有重复键的元数据仍被拒绝。导出中的旧诊断只按已知完整失败模板或明确诊断标记过滤，不把任意冒号建议当作失败，也不清理历史原件。

Same-user attackers may still race directory creation/binding or the final identity/permission check and replacement in R01 (temporary-root identity and cleanup), R04 (unchanged existing permissions and directory creation), R05/R07/R08. Production Python checkpoint serialization is descriptor-bound, but the final check/`os.replace` race and the compatibility filename-callback race remain. Swift distinguishes descriptor-bound APFS/HFS from capability gaps on FAT/exFAT or explicit ENOTSUP/EOPNOTSUPP/ENOSYS on other filesystems. Failed permission calls on APFS/HFS, including unexpected ENOTSUP, preserve the original and report an error. Unsupported volumes still cannot guarantee private access, and ordinary rename fallback does not provide every APFS check or rollback guarantee. Python checkpoints retain their own refusal rules: optional metadata errors cannot add mode access bits or lose the intended ACL; unexpected ACL reads, unpreserved nonempty constraints, or failed removal of inherited ALLOW entries reject the save. Production checkpoint saving is descriptor-bound, while load_checkpoint still passes a filename to its callback. Exit deadlines cover inactivity rather than progressing writes. Explicitly quitting after a hang preserves existing disk files but can lose unwritten progress; synchronous kernel I/O can still delay the UI. P09 (system preview translation without a uniform offline gate) and P10 (global clipboard) remain unchanged.
