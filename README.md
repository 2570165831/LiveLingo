# LiveLingo 0.1.0

面向英语课堂的本机转写、中文翻译和学习笔记工具，使用 SwiftUI 构建，支持 Apple 芯片 Mac，最低部署目标为 **macOS 14**。

## 源码、本机应用与发布包

开发源码和公开安装包可能处于不同版本，下面分别列出。

- **当前开发源码**的版本为 `0.1.0 / 20260929.4`，包含原生课堂工具栏、字幕翻译的输入前缀缓存、减少笔记完成后写盘、输入纠错边界，化学式和字面名称保留修正，以及按失败原因恢复字幕翻译。相邻前句补全失败时保留已完成的当前句；无法对应英文尾句的补全不再重复计算。当前句通过检查后先在课堂字幕中显示；有新字幕排队时先翻译新句，再按顺序补修前句，模型请求仍串行。待补修任务随课程保存，暂停、关闭再打开后可继续；原文或依赖前文改变时丢弃旧补修，已接受的当前译文不重复生成。修订、暂停或切换课堂会清除失效预览。短句也检查异常长译文，保留术语展开所需容差。明确命名的字母编号保留原文，并要求翻出命名动作；输入保护复用已编译的匹配规则。验收方法见下方“运行库与模型”。
- 录音中收到系统休眠通知时，停止采集并按正常收尾流程保存已收到的音频，明确提示休眠原因；唤醒后等待用户主动开始新录音。仅屏幕熄灭不会停止采集。该处理已通过模拟通知和录音文件回读测试，真实合盖与设备恢复仍需实机验证。
- 暂停期间发生的麦克风设备变化会在继续时处理；已取消或属于旧会话的恢复回调不能卡住或覆盖新请求。继续后保留首个回调的等待时间，避免因旧时间戳立即重启。更换设备及停止录音前会写完采样率转换器暂存的尾部音频；原录音格式保持不变。 自动恢复后，连续稳定采集时间和成功写入的音频均达到 30 秒才重置三次恢复额度；短暂来声、稀疏回调或积压音频不会单独重置，正常静音可以。该规则通过合成音频和真实保存流程检查，仍需真实硬件故障验证。
- 明确要求原样保留的多个标签或名称会一起保护，包括复数列表、同句并列的标签赋名，以及名称内部的撇号。普通引语和科学概念不因这项规则被当成字面名称；新增的并列保护不会延伸到下一句、下一行或普通转述。命名提示同时保留标签位置。仅识别有限的明确命名句式，不保证所有自然语言名称都被覆盖；占位符仍须完整还原。这类请求会增加部分输入和输出 token，不额外增加模型请求。
- 文字翻译的普通与精确模式同样保留公式和明确的字面名称，并检查名称是否完整还原；无效结果显示失败，不自动追加请求。原文通过独立文本字段传入，帮助模型完整翻译命令句；原文本身含同名字段时保留原有传入方式，避免混淆 JSON 示例。精确模式另外要求翻译普通引语，只按明确的字面名称或技术内容保留原文。手输文本不经过学术语音纠错，原有生成额度、超时和排队规则不变。固定样例中的漏句和名称改写有所改善，仍有修饰词遗漏及物理术语混用，不能据此认定所有句子都准确。
- 4B在原文含明确否定词时补充通用对照提示，帮助区分“不必／不得”“并非全部”等含义；这段否定提示只对4B启用。名称先保护，名称中的否定词不会触发这段提示。固定本机对照中，部分“禁止”被译成“必须”和非空被译成空的错误减少；普通引语仍有翻反、字幕仍可能漏掉外层命令，部分单位拼写和生硬表达也未修好。触发时增加104个输入token，不增加模型请求、输出额度或超时；没有普遍提速、省电或课堂准确率结论。
- 9B字幕将待译原文放入独立文本字段，帮助模型翻译“重复两次”“只返回数字”等课堂原话，减少把原话当指令执行。辅助识别提示与正文分开；字段名与原文冲突时沿用原有输入。4B和文字翻译保持原有处理。固定样例中部分漏译改善，但仍有普通英文引语未译、措辞生硬和引号不配对；不是全部语义错误已修复的证明。每次输入略有增加，请求次数、输出额度和超时不变；没有提速或省电结论。
- 自动补转可复用同一片段、相同音频内容和模型已返回的增强识别结果，减少重复模型计算；结果仍经过原有英文与异常文字检查。暂停、切换课堂、手动重试、音频变动及失败或取消的请求不沿用这份结果。首轮原始识别不增加缓存开销，邻近上下文仍单独识别并保留为待确认候选；重试额度不变。
- 翻译提示补充运动学中的 speed（速率）和 velocity（速度），包括平均值和瞬时值；日常动词、光速等固定说法仍按语境翻译。固定本机模型样例显示部分混淆减少，但角速率、方向变化问句及部分错误断言仍有反例，不能据此认定物理术语已全部修好。没有新增翻译请求或放宽译文检查。
- 语言模型进程空闲时等待新命令或实际的回收时间，减少固定间隔唤醒；回收条件、模型、翻译提示和生成额度不变。停止和输入断开会唤醒等待线程，暂停任务在模型卸载后仍可从保存状态继续。该改动减少的是已测工作进程等待点的唤醒，尚无整机省电比例。
- 模型确认保存、暂停或释放请求后，App 立即继续，减少定时检查回执造成的等待。取消仍须等模型确认，超时和进程退出仍按原有保护处理；重复回执不能覆盖已经确定的结果。该改动不改变模型输入、翻译提示、生成额度或译文检查。
- **本机应用**的实际版本以“关于 LiveLingo”显示为准；拉取源码不会自动更新已安装的 App。
- **公开离线安装包**为 `LiveLingo-0.1.0-20260924.0014-macOS14+-arm64.dmg`，内置构建号 `20260923.1`。公开标签按 9 月 24 日 00:14（悉尼时间）收到苹果公证通过结果的时间命名。签名、公证及验证范围见 [20260924 发布说明](RELEASE_NOTES_20260924.md)。

## 能做什么

- 从麦克风或系统音频（内录）接收英语，显示英文转写与中文翻译。
- 提供悬浮字幕、录音暂停和继续、双语历史及录音导出。
- 增量生成学习笔记，分别显示最近更新与整课内容。
- 课堂界面以字幕和笔记为主：宽窗口双栏阅读，窄窗口切换阅读内容；可关闭“跟随最新”查看先前字幕。课堂设置、文字翻译和笔记核对通过独立入口打开，提示详情展开时保留正文位置。
- 录音结束后可手动启动 9B 思考复查，保留笔记正文，单独显示意见；支持暂停和恢复。停止录音本身不会自动启动复查。
- 打开已保存课程，恢复字幕、笔记及可恢复的处理进度；采集始终等待用户主动开始。旧课程缺少来源或批次信息时会说明限制。
- 转写积压保存为待处理任务，可暂停、继续或主动重试；存在正文的修正先保留为候选，确认后再更新相关内容。
- 模型在本机运行。应用管理 MLX / MLX-LM 和转写进程，不需要 LM Studio。

转写使用 Parakeet TDT 0.6B v2，异常结果可回退到 Qwen3-ASR 1.7B；翻译与笔记使用 Qwen3.5 4B / 9B。最终 JSON 使用 Outlines 约束，明确的计算可由 Pint、SymPy 和 ChemPy 辅助检查。模型仍可能漏译、误译或给出错误知识；格式约束与计算检查不能保证内容正确。

## macOS 14 的功能限制与英文预览

macOS 14 可以使用内置模型做正式英文转写、中文翻译、学习笔记和复查。受系统版本限制的是 **“同步初译”**：它使用苹果翻译接口，需要 **macOS 15 或更新版本**。在 macOS 14 上这个开关不可用，中文需要等正式翻译完成；这不表示 macOS 14 不能翻译。

英文逐词预览是另一项功能：macOS 14 也可以使用，但需要系统具备可用的设备端英语识别资源，并获得语音识别授权。缺少资源时，新系统也可能无法显示逐词预览；正式英文转写仍由内置模型完成。

如果英文逐词预览不可用，可以先联网准备系统资源：

1. 打开 **系统设置 → 键盘 → 听写**。
2. 开启听写，并在语言中添加 **英语（美国）**。
3. 保持联网，等待系统准备语言资源，再打开 LiveLingo 检查预览是否可用。

资源由 macOS 管理，开启听写并不保证 LiveLingo 立即可用，最终以应用实际检测为准。操作入口见[苹果的听写说明](https://support.apple.com/en-euro/guide/mac-help/mh40584/mac)。这是可选的系统预览资源，与 DMG 已内置的正式转写模型不同。

## 开发构建

当前开发工具为 Xcode 27.0。目标应用的最低系统版本与构建工具自身的系统要求是两回事。

```sh
git clone https://github.com/2570165831/LiveLingo.git
cd LiveLingo
xcodebuild -project LiveLingo.xcodeproj -scheme LiveLingo \
  -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath work/DerivedData CODE_SIGNING_ALLOWED=NO build

xcodebuild -project LiveLingo.xcodeproj -scheme LiveLingo \
  -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath work/DerivedData CODE_SIGNING_ALLOWED=NO test
```

未签名 Release 可使用 `./Scripts/build-release.sh`。需要完整功能时，继续准备并组装运行库和模型。

`Scripts/recover-orphan-recordings.py` 检查异常退出后尚未收尾的 WAV。只在头部完整、编码支持且音频边界可确认时恢复；正常音频后的元数据、非零数据长度及结构不明确的文件不会被任意扩展。
**默认只报告，加 `--export` 才写出新文件，源文件始终只读，也不覆盖已有同名输出**。恢复期间源文件变化时，该次输出不计为成功；参数见其 `--help`。

### 运行库与模型

- 语言运行库版本见 [MLXRuntime.lock.json](Packaging/MLXRuntime.lock.json)，ASR 环境见 [ASRRuntime.lock.json](Packaging/ASRRuntime.lock.json)。这些文件不是完整的自动安装配方。
- `Scripts/prepare-mlx-runtime.py` 从已准备好的环境组装语言运行库并核对版本；不会创建环境或下载依赖。参数见其 `--help`。
- ASR 需要完整便携 CPython 树，不能直接用 venv 代替。
- 模型名称、来源与许可见 [第三方声明](Packaging/THIRD_PARTY_NOTICES.md) 及 [模型说明](Packaging/ModelNotices/)。模型目录结构须与 `Scripts/bundle-mlx-app.py` 的映射一致。
- MLX、Outlines Core 等原生依赖须使用兼容 macOS 14 的构建。打包脚本检查最低系统版本；安装最新依赖不能替代兼容性验证。
- 模型加载时的语法词表改用内置字符转换，保留每个原始字节和 token ID；未知 ByteLevel 字符仍拒绝，普通新增 token 仍按 UTF-8 编码，特殊 token 仍排除。词表仍在加载时准备，不把开销移到首次笔记。`test_grammar_bytes.py` 检查无效 Latin-1 字符、其他 Unicode、代理项及新增/特殊 token 边界；`test_grammar_vocabulary.py` 可用本地分词器核对中文、化学式和表情。构建步骤变快不等于整场翻译加速或耗电下降。
- 普通翻译和摘要会复用同一模型中完全相同的输入前缀，减少任务切换后重复读取固定提示。非思考模式的结构化笔记也可使用剩余额度，最多保存 256 个输入 token。内置且验证过的 9B 4-bit 配置，普通任务最多保存 768 个 token，缓存总上限为 148 MiB；其他配置仍是 512 个 token、128 MiB。每个已加载模型最多保留两份快照。9B 的两种翻译提示各需要约 73 MiB，旧 144 MiB 上限无法同时容纳，切换提示会重复计算；新上限可容纳两份。笔记不能挤掉字幕或普通摘要的快照，两份普通快照占满时不新增笔记缓存；普通任务需要空间时先释放笔记快照，再释放最久未使用的普通快照。优先复用最长的完全一致前缀，每个请求取得独立副本，语法约束状态分别创建。不复用生成答案、不裁剪输入；思考、带输出前缀的续写和断点恢复不读取新请求的前缀缓存，模型卸载时缓存一并释放。
- 笔记缓存的本机验证包括 94 项运行库检查，以及 4B、9B 共 44 次生成的 22 组对照，完整文本和 token 序列均一致；8 次中途恢复及 8 次完成结果重放通过。每档只有两组笔记缓存命中的计时样本，平均数、中位数和最长耗时均保留；这些结果不等于真实课堂准确率、普遍加速或整机省电。新增笔记快照会使用部分原来空闲的内存额度，总上限不变。
- 翻译前的字母拼读纠错只匹配完整词组，避免把 `This N two`、`alpha T plus` 等普通表达拼成化学缩写。铁离子名称纠错只使用紧跟该名称的 `Fe³⁺`，保留同段其他亚铁离子、反应起点及比较对象。相关正反例见 `SessionExporterTests.swift`；合成例句的通过情况不等于真实课堂准确率。
- 字幕翻译完整保留已识别的化学式、括号和电荷；公式标记遗漏、重复或变形时拒绝该次结果，流式字幕也隐藏未能还原的标记。单位、pH 和仪器名称保留可读形式，避免模型失去理解上下文所需的信息。当前句单独翻译；前句的可选修正仍可参考上下文，但化学式写法或数量改变时保留原有译文。辅助识别不再重复提示已经明确保护的公式。检查覆盖固定合成样例，不能保证任意化学式、语义或真实课堂准确率。

- 上一批仅对 4B 内容恢复中能识别的、带引语的 `translate "..." into/to ...` 请求，将原文放进 JSON 值并提示把整条命令译成中文，减少把课堂内容当作模型指令执行的情况。当时首译、预算恢复、其他内容恢复请求及 9B 处理保持原样，输出上限、时限和最多生成次数不变。两种对全部 4B 内容恢复加包装的试验均曾使正确样本丢失否定，已弃用。限定后的源码策略在上述 7 条旧失败文本中恢复了 6 条，另一条改错 JSON 键仍被拒收。23 条开发文本和 4 条新编、事先写明判断标准的文本，人工核对完整交付为 11/27→21/27；其中仍有 3 条错误或不完整结果被验收放行，尚需处理。当前源码完整测试 651 项通过、1 项跳过；用完全一致的请求重放既有 124 条标准字幕输出，全部请求、结果和验收决定与前一批源码一致。27 条内容恢复请求中 13 条改变，各增加 49–51 个输入 token，其余 14 条不变。这里只验证小批文本和原生翻译流程，未测真实课堂准确率、整场延迟或能耗，未安装、签名或发布新的 App。

### 签名与 DMG

签名材料和公证凭据不存入仓库。发布者必须显式提供自己的 Developer ID 身份、证书及钥匙串路径。

```sh
./Scripts/sign-offline-app.py --app work/OfflineCandidate/LiveLingo.app \
  --identity 'Developer ID Application: Example Name (TEAMID)' \
  --certificate /absolute/path/to/developer-id.cer \
  --keychain /absolute/path/to/login.keychain-db

./Scripts/build-offline-dmg.sh --app work/OfflineCandidate/LiveLingo.app \
  --identity 'Developer ID Application: Example Name (TEAMID)' \
  --keychain /absolute/path/to/login.keychain-db
```

DMG 顶层包含 App、“应用程序”快捷方式和使用说明。分发前还需使用自己的 `notarytool` 配置提交苹果公证，成功后执行 `stapler staple` 与 `stapler validate`；签名通过不等于公证通过。

`Scripts/run-qwen-service.sh`、`Scripts/install-qwen-service.sh` 和 `Packaging/*.command` 是历史服务与旧安装布局的辅助脚本，不属于当前安装步骤。
