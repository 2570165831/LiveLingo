# Bundled dependency notices and source

`runtime-manifest.json` in the enclosing LanguageRuntime records pinned Python packages and their direct license files. `AUDIT.json` records the verified collection scope.

- `native-source-notices`: exact Python source release notices; MLX uses its identified upstream Git revision.
- `native-cargo-notices`: exact Cargo.lock union and notice hashes. Optional, build and platform entries are included for coverage; this does not assert every crate is linked. MPL/CDDL source archives are under CorrespondingSource.
- `mlx-0.32.2-native`: MLX, Metal C++, fmt, JSON, nanobind and robin-map notices and source provenance.
- `CPython-3.13.7-20250902`: portable Python and upstream bundled dependency notices.
- `GCC-runtime-13.4.0`: source archive and runtime license/exception texts for SciPy's GNU runtime dependencies; see its provenance limitation.
- `ASR-audio`: publisher notices, exact binary provenance and all seven audio library sources. libogg 1.3.5, libvorbis 1.3.7, FLAC 1.4.3 and Opus 1.4 are statically linked into the LGPL libsndfile binary and are included as rebuild inputs, together with LAME, mpg123 and libsndfile. Their original copyright/license texts are retained. The original publisher script and darwin.cmake are inside the libsndfile archive. The added `offline-rebuild.sh` uses the bundled archives without downloads. Original and bundled hashes/sizes are separate in inventory.json.

Sources are included for inspection and rebuilding the corresponding third-party components. The original upstream build recipes are retained; a byte-identical rebuild is not asserted. Dynamically loaded library files are present in the portable Python directories. A modified local App will require a fresh local code signature before macOS can run it. No additional restriction on rights granted by the respective third-party licenses is intended.

The offline audio recipe generates a libvorbis configure companion with the obsolete `-force_cpusubtype_ALL` flag removed, matching the publisher recipe's compatibility step. Its original configure file stays unchanged. It explicitly supplies CMake's 3.5 compatibility policy for older libsndfile build files when using CMake 4. GNU GCC 13's upstream source lacks native AArch64 Darwin target support; the documentation check uses a supported x86_64 Darwin cross target. The downstream compiler patches used for the shipped SciPy wheel are not established by compiler-version metadata alone.

`source-preparation/SourceArchiveAudit.json` records source preparation, retained license hashes, explicitly optional omissions and dated file modifications. Each archive carries `MODIFICATIONS.json`; modified source files carry a contributor/date comment. Build scripts, configure inputs, Automake test includes, man pages, Texinfo sources and prebuilt GCC manuals are retained. The GCC subset supports C, C++ and Fortran; unselected frontends and optional regression/publication assets are omitted, rather than entire documentation directories. Inferno inline test modules are retained. Neutral GNU Info example replacements preserve byte offsets.

`source-preparation/PrivacyResources.json` binds reviewed resources to exact App-relative paths and hashes. Source members and archive ownership/timestamps are checked; native load-command strings are checked for user/build paths. Format checks do not assert arbitrary binary contents are private-data free. Offline configure/dry-run tests are provided by the project; the GCC check covers top-level configuration and documentation dependencies, not a full compiler bootstrap. Cargo crates have no configure script; their manifests/library entry points are checked, and a Cargo build requires a separately available offline toolchain/dependency cache. No matching rebuilt binary is claimed.

Runtime `MODIFICATIONS.json` files record Python AST-preserving encoding normalization, metadata/RECORD preparation, certificate label omission and portable native load paths. Each model directory carries its own dated `MODIFICATIONS.json`. Cargo attribution declarations retain package/license/author provenance, with dependency and feature build tables omitted. Filenames accidentally matched by the old notice collector are listed separately in its inventory. Pillow notices originally below Tests are preserved under test-notices; both provenance and inventory record the upstream path.
